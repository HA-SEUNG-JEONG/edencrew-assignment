# 관심종목 앱: Flutter 과제 1

국내 주식 관심종목을 관리하는 앱이다. `관심` · `검색` · `종목상세` 세 화면을 Flutter로 구현했다.
데이터는 Naver endpoint 4종에서 실시간으로 가져온다.

과제 요구사항은 [`docs/ASSIGNMENT.md`](docs/ASSIGNMENT.md), 데이터 연동 규격은
[`docs/NAVER_API.md`](docs/NAVER_API.md)에 있다.

---

## 실행 방법

```bash
flutter pub get
flutter run
```


| 항목                | 값               |
| ----------------- | --------------- |
| Flutter           | 3.44.9 (stable) |
| Dart              | 3.12.2          |
| `environment.sdk` | `^3.11.5`       |


**확인한 환경**은 iOS 시뮬레이터(iPhone 15 Pro, 393×852)다. 시안 프레임과 논리 해상도가
같기 때문에 여백을 눈으로 대조하기 쉽다.

**웹(Chrome)에서는 동작하지 않는다.** Naver endpoint가 CORS를 허용하지 않기 때문이다.
스타터 README에 명시된 제약과 동일하다.

### 폰트

**스타터가 제공한 방식을 그대로 사용했다.** `assets/fonts/`의 Noto Sans KR(Regular/Medium/Bold)과
`pubspec.yaml` 등록, `AppTheme.dark`의 기본 서체 지정을 모두 변경하지 않았다. `google_fonts`
같은 패키지로 교체하면 첫 프레임에서 네트워크 폰트 다운로드가 발생하기 때문에, 로컬 등록보다
얻을 수 있는 이점이 없다.

### 추가로 구현한 선택 항목

- **Pull to refresh**: 관심 목록에 적용했다(`AlwaysScrollableScrollPhysics`를 지정해서 목록이 짧아도 동작한다).
- **관심종목 스와이프 삭제**: 오른쪽에서 왼쪽으로 스와이프하면 삭제되고, 해제 토스트가 함께 표시된다.
- **검색 입력 디바운스**: 300ms를 적용했다.
- **검색어 입력 중 로딩 표시**
- **일별 시세 페이지 캐시**: 기간 탭으로 되돌아오면 다시 요청하지 않는다.

구현하지 않은 선택 항목은 정렬 기준과 관심 목록의 로컬 저장, 최근 검색어, 토스트 애니메이션,
차트 축 라벨 · 거래량 바 · 영역 채우기 · 크로스헤어다.

## 기술 선택과 이유

### 상태관리: `ChangeNotifier` + `InheritedNotifier` (패키지 없음)

전역으로 공유해야 하는 상태는 **관심 목록 · 시세 캐시 · 정렬 기준 세 가지뿐**이다. 검색어와
검색 결과, 상세 화면에서 선택한 기간은 해당 화면 밖에서 사용할 일이 없어서 각 `State`에 보관했다.

공유 범위가 이 정도라면 Riverpod과 Bloc이 제공하는 기능(의존성 그래프, 자동 폐기, 이벤트 추적)보다
학습 비용과 설정 비용이 더 크다. Flutter에 내장된 `InheritedNotifier`만으로도 같은 결과를 얻을 수 있다.

```dart
// lib/app_state.dart
class AppScope extends InheritedNotifier<AppState> { ... }

extension AppScopeContext on BuildContext {
  AppState get appState => dependOnInheritedWidgetOfExactType<AppScope>()!.notifier!;
}
```

`context.appState`는 스타터가 이미 사용하고 있는 `context.colors` / `context.dimens`와 사용
방식이 같기 때문에, 화면 코드에서 이질감이 없다.

`AppState`가 `StockRepository`를 필드로 보유하는 이유는 하나다. **일별 시세 페이지 캐시가
저장소 인스턴스의 필드**이기 때문에, 상세 화면도 같은 인스턴스를 사용해야 캐시가 유지된다.

### 폴더 구조: 레이어 3단

```
lib/
  app_state.dart          공유 상태 + InheritedNotifier
  domain/                 models.dart · format.dart      (Flutter 의존 없음)
  data/                   stock_repository.dart · dto/ · codec/ · daily_price_parser.dart
  ui/                     화면 3개 + common.dart · candle_chart.dart
  theme/                  (스타터 제공 · 토큰 1건 추가 — 아래 "디자인 토큰" 참고)
```

`domain/`은 `dart:` 외에 아무것도 import 하지 않는다. 그 덕분에 포맷터와 파서, DTO 테스트가
`flutter_test`의 위젯 바인딩 없이 순수 Dart로 실행된다. 전체 30개 가운데 18개가 여기에 해당한다.

화면이 3개인 규모에서 feature-first(`features/watchlist/...`) 구조로 분리하면 디렉터리가
코드보다 많아진다. 레이어 3단 구조가 이 규모에 적합하다.

### 주요 패키지


| 패키지    | 용도                    | 대안을 안 쓴 이유                                  |
| ------ | --------------------- | ------------------------------------------- |
| `http` | Naver endpoint 호출     | `dio`의 인터셉터·재시도가 필요할 만큼 호출이 복잡하지 않다         |
| `html` | `sise_day.naver` 표 파싱 | 정규식으로 `<td>`를 추출하면 네이버가 마크업을 조금만 변경해도 조용히 깨진다 |


**추가하지 않은 항목**은 차트 패키지와 `intl`, 상태관리 패키지, 로컬 저장소다.
`intl`은 천 단위 구분과 `MM.DD` 형식만 사용하려고 도입하기에는 비용이 크다. `domain/format.dart`
43줄로 같은 기능을 구현했다.

### 차트: `CustomPainter` 직접 구현

과제 문서가 지적한 대로 "캔들을 지원하면서 토큰 색과 시안 여백까지 맞추기 쉬운 패키지"가
없다. 필요한 것은 캔들 몸통과 심지를 그리는 `drawRect` 두 개뿐이라서 [`lib/ui/candle_chart.dart`](lib/ui/candle_chart.dart)
95줄로 구현했다. 패키지를 도입했다면 색 토큰을 우회하거나 패키지 내부 여백을 조정해야 했다.

- 색을 결정하는 기준은 **당일 시가 대비 종가**다. 전일비를 기준으로 색을 결정하면, 몸통은 아래로
뻗는데 색은 상승으로 표시되는 경우가 생긴다.
- 1년(약 250봉) 구간에서는 몸통 폭이 1px 미만으로 줄어들기 때문에 `max(1, slot * 0.6)`으로
하한을 제한했다.
- 축 라벨 · 거래량 바 · 영역 채우기는 선택 항목이라서 그리지 않았다.

### 디자인 토큰: 추가 1건

**추가: `AppColors.surfaceScrim`** (`AppPalette.blackAlpha50` = `0x80000000`)

정렬 바텀시트의 스크림은 시안에서 검정 50%인데, Material 기본값은 `black54`(54%)라서 더
진하다. `barrierColor`에 `Color(0x80000000)`을 직접 사용하면 "화면 코드가 원색 리터럴을
사용하지 않는다"는 프로젝트 규약을 위반하므로, 팔레트와 시맨틱 두 단계로 토큰을 정의했다.

**사용하지 않은 토큰**은 `priceUpBg` · `priceDownBg` · `priceFlatBg`다. 시안에서 등락 표기가
배경색 없는 텍스트이기 때문에 전경색(`priceUpText` 등)만 사용했다.

## 직접 판단한 부분과 이유

### 토스트: 2초 표시, 자동 소멸, 큐 없음

`ScaffoldMessenger`의 floating `SnackBar`를 사용했고, [`common.dart:164`](lib/ui/common.dart)
한곳에 모았다.

- **2초**: 아이콘과 한 줄 문구를 읽기에 충분하면서, 별을 연속으로 누르는 동안 화면을 계속
가리지는 않는 길이다.
- **큐를 비우고 새로 표시한다**(`clearSnackBars`). 기본 동작은 토스트를 순서대로 대기시키는데,
별을 빠르게 두 번 누르면 이미 해제된 종목에 "등록되었습니다"라는 문구가 뒤늦게 표시된다.
**현재 상태와 어긋나는 문구는 표시하지 않는 편이 낫다.**
- **아래로 스와이프해서 즉시 닫을 수 있다**(`dismissDirection: down`). 위로 스와이프하는
기본값은 토스트가 하단에 있을 때 방향이 어색하다.
- `Scaffold`는 앱 전체에 **하나만** 배치했다(`main.dart`의 `_HomeShell`). 화면마다 배치하면
`ScaffoldMessenger`가 분리되어 토스트가 중복으로 표시된다.
- 등장 애니메이션과 퇴장 애니메이션은 `SnackBar` 기본값을 그대로 사용했다(선택 항목이다).

### 로딩: 이미 있는 값은 지우지 않는다


| 화면        | 처리                                                                 |
| --------- | ------------------------------------------------------------------ |
| 관심 (첫 진입) | 시세 없는 행만 스켈레톤 (`feedbackSkeleton`). 종목명과 코드는 시세가 없어도 알 수 있는 값이라서 그대로 표시한다 |
| 관심 (새로고침) | 값을 유지한 채 헤더 버튼만 스피너로 바꾼다. 전면 로딩으로 덮으면 화면이 깜빡인다                     |
| 검색        | 이전 결과가 있으면 그대로 두고, **없을 때만** 스피너. 디바운스 대기 중도 로딩으로 간주한다               |
| 상세 (차트)   | 로딩 중에도 `height: 152`를 유지한다. 그러지 않으면 아래 요약 카드와 표의 위치가 위아래로 이동한다             |
| 상세 (일별)   | `일별 시세` 제목 옆 12px 스피너. 표 자리를 비우지 않는다                               |


### 네트워크 에러: 실패 범위에 따라 다르게 처리한다

- **관심 목록**: 보여줄 시세가 **하나도 없을 때만** 전면 에러와 `다시 시도` 버튼을 표시한다
(`AppState.blankError`). 일부만 실패하면 이미 받은 시세를 유지한다. **오래된 시세라도
빈 화면보다 낫다.**
- **검색**: 결과 자체가 없으므로 전면 에러와 `다시 시도` 버튼을 표시한다.
- **개별 시세 1건**(관심 등록 · 상세 진입): 해당 행을 스켈레톤으로 유지하는 것으로 충분하다.
새로고침하거나 다시 진입하면 재요청된다.
- **일별 시세**: 오류를 표시하지 않고 표를 비운다. 헤더와 시세, 차트는 이미 그려져 있어서
화면이 깨지지 않는다.
- 처리하는 예외를 `HttpException`으로 좁히지 않았다. 실기기에서는 `SocketException`과
`ClientException`, `FormatException`도 발생하기 때문이다.

### 긴 종목명 오버플로

전부 `maxLines: 1`과 `TextOverflow.ellipsis`를 적용했다. 종목명 쪽만 `Expanded`로 감싸고 가격
컬럼은 자연 크기로 유지했다. **긴 이름이 가격 컬럼을 밀어내면 행끼리 세로 정렬이 어긋난다.**
세로로 훑어 읽는 목록에서 가장 눈에 띄는 결함이기 때문에 이름을 자르는 방식을 선택했다.

### 긴 검색어: 20자에서 자른다

결과 없음 문구에는 검색어가 그대로 삽입되는데, 사용자가 긴 문자열을 붙여넣으면 안내 문구가
밀려난다. **20자를 초과하는 부분은 `…`로 줄였고**([`search_screen.dart:129`](lib/ui/search_screen.dart)),
`EmptyState` 본문도 `maxLines: 2`로 제한했다. 검색어 원문보다 "왜 결과가 없는지"가
더 중요한 정보다.

### 시세를 받지 못한 행의 정렬 위치: 맨 아래

`현재가순`과 `등락률순`에서는 시세가 없는 행을 **비교에서 제외하고 맨 아래에 배치했다**
([`app_state.dart:107`](lib/app_state.dart)).

0으로 가정하면 하락 종목보다 위에 표시된다. "-3% 종목보다 위에 있는, 값이 없는 행"은 정렬이
잘못된 것처럼 보인다. 값이 없는 상태와 값이 0인 상태는 다르다.

`가나다순`은 시세가 없어도 종목명을 알 수 있기 때문에 모든 행이 정렬된다.

### 가나다순에서 한글을 영문보다 앞에 배치: **기존 동작 변경**

`String.compareTo`는 코드포인트 순서를 따르기 때문에 영문(`0x41` 이상)이 한글 음절(`0xAC00` 이상)보다 항상 작다.
그대로 두면 `LG에너지솔루션`과 `SK하이닉스`가 목록 맨 위에 표시된다. 국어사전과 증권 앱의 관행은
한글을 먼저 배치하는 것이고, `가나다순`이 기본 정렬이기 때문에 **앱을 실행하자마자 보이는 차이다.**

정렬 키 앞에 한글 여부를 나타내는 플래그를 붙여서 한 줄로 해결했다. `intl`의 `Collator`는
도입하지 않았다.

```dart
static String _nameKey(String name) {
  final int first = name.isEmpty ? 0 : name.codeUnitAt(0);
  final bool hangul = first >= 0xAC00 && first <= 0xD7A3;
  return '${hangul ? 0 : 1}$name';
}
```

한글 음절 블록 안에서는 코드포인트 순서가 곧 가나다 순서이기 때문에 추가 처리가 필요 없다.
자세한 경위는 [`docs/fixes/2026-09-12-watchlist-name-sort-collation.md`](docs/fixes/2026-09-12-watchlist-name-sort-collation.md)에 정리했다.

### 앱 첫 실행 시 관심 목록

## 막혔던 지점과 어떻게 접근했는지

### 1. EUC-KR 응답이 전부 깨졌다

`polling.finance.naver.com`과 `sise_day.naver`는 EUC-KR로 응답하는데, `http` 패키지의
`response.body`는 `Content-Type`에 charset이 없으면 **latin1로 디코딩**한다. 그래서 한글이
전부 깨진 상태로 출력됐다.

`bodyBytes`로 응답을 받아서 직접 디코딩하는 방식으로 변경했다. Dart 표준 라이브러리에 EUC-KR
코덱이 없기 때문에, `charset_converter`(플랫폼 채널에 의존한다) 대신 **순수 Dart로 작성한
CP949 디코더를 사용했다**([`lib/data/codec/`](lib/data/codec/), 테이블을 포함해 196줄이다).
플랫폼 의존성이 없어서 위젯 테스트에서도 그대로 실행된다. mock 응답으로 디코딩을 검증하는
테스트는 그래서 작성할 수 있었다.

### 2. 일별 시세의 전일비에 부호가 없다

`sise_day.naver` 표의 전일비 `<td>`에는 절댓값만 들어 있다. 방향은 안쪽 `<em>` 태그의
클래스로만 구분되는데, `bu_pup`(상승) / `bu_pdn`(하락) / `bu_pn`(보합) 세 가지다. 텍스트만
추출하면 하락이 상승으로 뒤집힌다.

`html` 패키지로 파싱해서 `em`의 클래스를 읽어 부호를 붙였다
([`daily_price_parser.dart:62`](lib/data/daily_price_parser.dart)). 실제 응답 HTML 3종을
`assets/mock/`에 저장해 두고, 이를 기반으로 파서 테스트 5개를 작성했다.

### 3. 마지막 페이지를 넘겨 요청하면 같은 데이터가 반복된다

`1년` 탭은 25페이지가 필요한데, 상장한 지 얼마 되지 않은 종목은 페이지가 그만큼 존재하지
않는다. 네이버는 범위를 넘는 `page` 요청에 **404를 반환하지 않고 마지막 페이지를 그대로 다시
반환한다.** 그대로 두면 같은 10행이 목록 끝에 여러 번 누적된다.

페이지네이션(`table.Nnavi`)의 링크에서 가장 큰 `page` 값을 읽어 `lastPage`로 지정하고, 요청
상한으로 사용했다. 페이지 링크가 아예 없는 응답(미상장 코드 등)은 요청한 페이지를 `lastPage`로
설정한다. 이 판정만 테스트 4개로 검증했다.

### 4. 기간 탭을 누를 때마다 처음부터 다시 요청한다

`1개월`(2페이지)에서 `1년`(25페이지)으로 이동한 뒤 다시 `1개월`로 돌아오면 27페이지를 요청한다.  
이는 과제 문서에 제시된 "**페이지 요청을 필요한 만큼만 하고 재사용하도록 구성했는지**"라는
기준에 정면으로 위배된다.

저장소는 종목코드별로 받은 페이지를 `Map<int, List<DailyPrice>>`에 누적하고 **부족한 페이지만**
추가로 요청한다([`stock_repository.dart:79`](lib/data/stock_repository.dart)). 위 시나리오는
2 + 23 + 0 = 25페이지로 완료된다. `MockClient`로 요청 횟수를 세는 테스트를 작성해서 이 동작을
고정했다.

이 캐시가 저장소 인스턴스의 필드이기 때문에, `AppState`가 저장소를 보유하고 상세 화면에
전달한다. 상세 화면이 자체 저장소를 새로 생성하면 캐시가 매번 비어 버린다.

### 5. 시안 대조를 눈으로 하면 계속 틀린다

처음부터 Figma 디자인 시안과 제공된 플러그인을 활용해야 했는데, PNG를 직접 다운로드해서
작업했기 때문에 시간이 오래 걸렸다.

대조 기록은 [`docs/fixes/`](docs/fixes/)에 남겼다. 두 번째 문서가 첫 번째 문서의 오분류
(빈 상태를 "시안에 없는 상태"로 분류한 것)를 정정하고 있다.
